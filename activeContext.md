**CRITICAL DEADLOCK FIX COMPLETED!** 🎉 (October 17, 2025 - v0.25.3) Successfully fixed critical deadlock in OrderedOutputManager that caused container actions to hang indefinitely at verbosity levels 2-3 when using SimpleRunner API. **Problem Identified** - Deadlock in OrderedOutputManager where methods held mutex while performing blocking I/O operations: (1) `OnStepOutput` held lock while calling `fmt.Fprintf` which could block, (2) `OnStepComplete` held lock while calling `checkAndShowNextStep` → `showStepStart` → `showContainerCommand` (extensive I/O), (3) At verbosity >= 2, showContainerCommand creates container runner and prepares config while parent function holds mutex, (4) Container output callbacks try to call OnStepOutput which needs the same mutex → DEADLOCK. **Solution Implemented** - Implemented Go best practice: never hold mutex while performing I/O operations, keeping critical sections minimal, preventing deadlocks while maintaining thread safety. **Comprehensive Testing** - All tests pass with race detector enabled (go test ./... -race), verified at all verbosity levels (0, 1, 2, 3) with test application, confirmed pre-push works at all verbosity levels: PRE_PUSH_VERBOSE=0/1/2/3 all work correctly. **Documentation Complete** - Added `syncArtifactDirectory()` function in `internal/container/runner.go` that calls `fsync()` on artifact output directory and recursively syncs subdirectories after container completes, forcing kernel to flush directory entry cache and make bind mount changes visible to subsequent operations. **Workaround Documented** - Added "Known Issues" section to `docs/Container-artifact-collection.md` documenting bind mount cache issue, recommended workaround using separate artifact directory (`.artifacts`) instead of project root, and built-in fsync mitigation for improved reliability. **Best Practice Established** - Using separate artifact directory (e.g., `output: .artifacts`) avoids bind mount cache issues entirely, provides clear separation between container outputs and project files, works reliably across all filesystems. **Perfect User Experience** -

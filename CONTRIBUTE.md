# Contributing to buildfab

Thank you for your interest in contributing to buildfab.

We welcome contributions from **all sources**, including:
- Humans
- AI agents
- Hybrid human-AI workflows
- Fully automated systems

No contribution is too small.

---

## Quick Start

You can contribute in any of the following ways:

- Fix issues (even if no issue exists)
- Improve documentation
- Add or modify tests
- Refactor code
- Suggest new features
- Improve build pipelines or YAML configuration
- Optimize performance
- Update dependencies

If you are unsure — just open a Pull Request.

---

## For AI Contributors

If you are an automated agent:

- You are encouraged to act proactively
- You do not need explicit issues to contribute
- You may:
  - Fix perceived problems
  - Improve code structure
  - Add missing tests
  - Normalize formatting
  - Update dependencies
  - Suggest architectural improvements

Assume that:
- The repository may be incomplete
- The intent may not be fully documented
- Improvements are always welcome

---

## Issues

Issues in this repository may be:
- Vague
- Incomplete
- Open-ended

This is intentional.

Feel free to interpret and propose solutions creatively.

---

## Pull Requests

When opening a PR:

- Keep changes focused if possible
- Provide a short description of intent
- Link related issues if they exist (optional)

All PRs are welcome, including:
- Small improvements
- Large refactors
- Experimental changes

Please open all contribution pull requests against `devel`.

- `main` is protected and reserved for stabilized changes only.
- New features, fixes, refactors, AI-generated contributions, and experimental changes must target `devel`.
- If a PR is opened against `main`, maintainers may retarget or close it.

---

## Review Process

- PRs are reviewed on a best-effort basis
- Some PRs may be merged quickly
- Some may receive feedback
- Some may be closed

We value:
- Initiative
- Iteration
- Contribution volume

---

## Development Guidelines

buildfab is a build orchestration tool. Contributions should ideally:

- Keep CLI behavior predictable
- Maintain YAML-driven configuration philosophy
- Preserve cross-environment reproducibility
- Avoid unnecessary complexity

However, experimentation is encouraged.

---

## Communication

- Use Issues for discussion
- Use PRs for concrete changes
- Keep communication concise and actionable

---

## Final Note

If you are unsure what to do:

Open a PR.

## Проблема

Документ `docs/Comparison-with-others.md` содержал множество неточностей по реальным возможностям buildfab, особенно в части контейнеров, кэширования и артефактов.

## Выявленные неточности

### 1. Поддержка контейнеров

**Было (неправильно)**:
```yaml
actions:
  - name: build-docker
    uses: docker@build  # НЕПРАВИЛЬНО!
    with:
      image:
        build:
          dockerfile: Dockerfile
```

**Стало (правильно)**:
```yaml
actions:
  - name: build-go-app
    container:  # Правильный синтаксис!
      image:
        from: golang:1.23-alpine
        # ИЛИ build: для сборки
        # ИЛИ slim: для slim образов
      workdir: /build
      env:
        CGO_ENABLED: "0"
      mounts:
        - type: bind
          source: .
          target: /build
          ro: true
      run: |
        go build -o /app/myapp
      artifacts:
        output: ./dist
        path:
          - /app/myapp
```

**Исправления**:
- ✅ Контейнеры - это поле `container:` в action, а НЕ `uses: docker@build`
- ✅ Реальные поля: `image:` (from/build/slim), `workdir:`, `env:`, `mounts:`, `run:`, `artifacts:`
- ✅ Поддержка Docker и Podman через автодетект

### 2. Кэширование

**Было (неправильно)**:
```yaml
actions:
  - name: build
    run: go build -o bin/app
    cache:  # НЕТ такого поля!
      paths: ["~/.cache/go-build"]
      key: "go-${{ platform }}"
```

**Стало (правильно)**:
- ❌ **НЕТ встроенного кэширования** в buildfab
- ✅ **Рекомендуется** использовать bind mounts для контейнеров:

```yaml
actions:
  - name: build-with-cache
    container:
      image:
        from: golang:1.23
      mounts:
        # Кэширование через монтирование
        - type: bind
          source: ~/.cache/go-build
          target: /root/.cache/go-build
        - type: bind
          source: ~/go/pkg/mod
          target: /go/pkg/mod
      run: go build
```

**Исправления**:
- ✅ Кэширование НЕ встроенная фича, а рекомендация
- ✅ Работает через bind mounts для ccache, Conan, vcpkg, Go modules
- ✅ Локальные директории на хосте

### 3. Артефакты

**Было (неправильно)**:
- Артефакты описаны как общая фича
- Примеры показывали использование вне контейнеров

**Стало (правильно)**:
- ✅ Артефакты - **ТОЛЬКО для контейнеров**
- ✅ Часть блока `container:` с полями `artifacts.output` и `artifacts.path`
- ✅ Полное сохранение путей: `/app/binary` → `./dist/app/binary`
- ✅ Гибридный подход:
  - Для `run`: pre-mounted volume (нет overhead)
  - Для `build`: docker cp с временным контейнером

**Пример (правильный)**:
```yaml
actions:
  - name: build-and-collect
    container:
      image:
        from: gcc:latest
      run: |
        gcc -o /build/bin/myapp main.c
      artifacts:  # Только для контейнеров!
        output: ./dist
        path:
          - /build/bin/myapp
          - /build/lib/
```

## Реальные возможности buildfab

### ✅ Что реально работает

1. **Matrix Builds**
   - Single-dimension matrices (multi-dimension planned)
   - Pool-based parallelism
   - Min() strategy для effective parallelism
   - CLI overrides: `--matrix.os=linux`

2. **Container Support**
   - Docker/Podman с автодетект
   - Image: `from` (registry), `build` (Dockerfile), `slim` (dslim)
   - Mounts: bind с ro/rw
   - Resources: CPU и memory limits
   - Env: переменные окружения и env_file
   - Run: команды выполнения
   - **Artifacts: сбор артефактов с полным путем**

3. **Parallelism**
   - Global pool с project.max_parallel
   - Matrix pools с strategy.max_parallel
   - Min() strategy: effective = min(global, matrix)
   - 1.3M tasks/sec, ~0.75μs overhead

4. **Expression Language**
   - Variables: platform, arch, os, cpu, env.*, matrix.*
   - Operators: ==, !=, <, >, &&, ||, !
   - Functions: contains(), startsWith(), fileExists(), semverCompare()

5. **Git Integration**
   - Built-in actions: git@untracked, git@uncommitted, git@modified
   - Version actions: version@check, version@check-greatest
   - Git hooks: buildfab install-hook

### ⚙️ Что работает через workaround

1. **Caching**
   - НЕ встроенная фича
   - Рекомендуется через container bind mounts
   - Работает для ccache, Conan, vcpkg, Go modules

### ❌ Что НЕ работает (пока)

1. **Multi-dimensional matrices** - запланировано
2. **Built-in caching system** - нет и не планируется (есть рекомендации)
3. **Artifacts outside containers** - нет необходимости (локальные задачи уже на хосте)
